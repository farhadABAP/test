2. Modern ABAP Syntax

ABAP Cloud enforces modern syntax. Classic constructs like WRITE for output, TABLES declarations, and obsolete statements are restricted. You must be fluent in constructor expressions and functional programming constructs.

2.1 Constructor Expressions Overview

Expression Purpose Returns
VALUE Construct a structure, table, or elementary value Structured or table value
REDUCE Aggregate values from an internal table into a single result Single value or structure
FOR Iterate over a table or generate a sequence inside VALUE/REDUCE Iteration expression
COND Conditional expression (if-then-else) Value based on condition
SWITCH Case-like expression based on a value Value based on case
FILTER Filter an internal table Filtered table

2.2 VALUE – Constructing Values

VALUE creates a value from scratch. It is used for structures, internal tables, and elementary types.

Structures

" Define a structure type
TYPES: BEGIN OF ty_person,
         name TYPE string,
         age  TYPE i,
       END OF ty_person.

" Construct a structure
DATA(ls_person) = VALUE ty_person( name = 'Alice' age = 30 ).

Internal Tables

" Simple table
DATA(lt_numbers) = VALUE i_table( ( 1 ) ( 2 ) ( 3 ) ( 4 ) ).

" Table of structures
TYPES: BEGIN OF ty_flight,
         carrid TYPE s_carr_id,
         connid TYPE s_conn_id,
       END OF ty_flight.

DATA(lt_flights) = VALUE ty_flight_table(
  ( carrid = 'LH' connid = '0400' )
  ( carrid = 'AA' connid = '0017' )
).

2.3 REDUCE – Aggregation

REDUCE iterates over an internal table and accumulates a result. It is the modern replacement for LOOP AT ... SUM or manual accumulation.

DATA(numbers) = VALUE i_table( ( 1 ) ( 2 ) ( 3 ) ( 4 ) ( 5 ) ).

" Sum
DATA(sum) = REDUCE i( INIT x = 0 FOR n IN numbers NEXT x = x + n ).
" Result: 15

" Maximum
DATA(max) = REDUCE i( INIT m = 0 FOR n IN numbers NEXT m = COND #( WHEN n > m THEN n ELSE m ) ).
" Result: 5

" Minimum
DATA(min) = REDUCE i( INIT m = 999 FOR n IN numbers NEXT m = COND #( WHEN n < m THEN n ELSE m ) ).
" Result: 1

REDUCE with a Filter Condition

" Sum only even numbers
DATA(sum_even) = REDUCE i(
  INIT s = 0
  FOR n IN numbers
  WHERE ( n MOD 2 = 0 )
  NEXT s = s + n
).
" Result: 6  (2 + 4)

2.4 COND and SWITCH

" COND – if-then-else
DATA(lv_text) = COND string(
  WHEN sy-subrc = 0 THEN 'Success'
  ELSE 'Failure'
).

" SWITCH – case-like
DATA(lv_category) = SWITCH string( lv_score
  WHEN 1 THEN 'Low'
  WHEN 2 THEN 'Medium'
  WHEN 3 THEN 'High'
  ELSE 'Unknown'
).

2.5 FOR – Iteration Expressions

" Build a table from an existing table (mapping)
DATA(lt_names) = VALUE string_table(
  FOR ls_person IN lt_people
  ( ls_person-name )
).

" Build a table with a condition
DATA(lt_adults) = VALUE ty_person_table(
  FOR ls_p IN lt_people
  WHERE ( ls_p-age >= 18 )
  ( ls_p )
).

3. Internal Tables

Internal tables are the backbone of ABAP programming. Choosing the right table type is critical for performance and is a common exam topic.

3.1 Table Type Comparison

Table Type Key Access Read Complexity Best For
Standard Non-unique (default) Index + key O(n) for key access General purpose, sequential processing
Sorted Unique or non-unique Index + key O(log n) for key access Large tables with frequent key reads, partial key access
Hashed Must be unique Key only (no index) O(1) constant time Very large tables, frequent unique key reads
📌 Exam Rule of Thumb
  • Need index access (e.g., loop with counter)? → Standard
  • Need fast key reads on a large table with non-unique keys? → Sorted
  • Need constant-time unique key access on a huge table? → Hashed

3.2 Declaring Internal Tables

" Standard table
DATA lt_std TYPE STANDARD TABLE OF mara.

" Sorted table with unique key
DATA lt_sorted TYPE SORTED TABLE OF mara WITH UNIQUE KEY matnr.

" Hashed table with unique key
DATA lt_hashed TYPE HASHED TABLE OF mara WITH UNIQUE KEY matnr.

" Modern inline declaration
DATA(lt_inline) = VALUE i_table( ( 1 ) ( 2 ) ( 3 ) ).

3.3 Reading from Internal Tables

" Standard table – READ TABLE
READ TABLE lt_std INTO DATA(ls_mara) WITH KEY matnr = 'ABC'.
IF sy-subrc = 0.
  " found
ENDIF.

" Sorted table – binary search
READ TABLE lt_sorted INTO DATA(ls_sorted) WITH KEY matnr = 'ABC'
  BINARY SEARCH.

" Hashed table – direct key access
READ TABLE lt_hashed INTO DATA(ls_hashed) WITH TABLE KEY matnr = 'ABC'.

" Modern expression – table expression
TRY.
    DATA(ls_row) = lt_std[ matnr = 'ABC' ].
  CATCH cx_sy_itab_line_not_found.
    " not found
ENDTRY.

3.4 Looping with Modern Syntax

" Classic loop with work area
LOOP AT lt_std INTO DATA(ls_work).
  " process ls_work
ENDLOOP.

" Loop with field symbol (more performant)
LOOP AT lt_std ASSIGNING FIELD-SYMBOL(<ls_row>).
  " process <ls_row>
ENDLOOP.

" Loop with index
LOOP AT lt_std INTO DATA(ls_idx) FROM 1 TO 10.
  " process first 10 rows
ENDLOOP.

3.5 Finding the Maximum – Three Approaches

DATA(lt_nums) = VALUE i_table( ( 45 ) ( 12 ) ( 89 ) ( 34 ) ( 67 ) ).

" Approach 1: LOOP
DATA(lv_max1) = 0.
LOOP AT lt_nums INTO DATA(lv_n).
  IF lv_n > lv_max1.
    lv_max1 = lv_n.
  ENDIF.
ENDLOOP.

" Approach 2: REDUCE
DATA(lv_max2) = REDUCE i(
  INIT m = 0
  FOR n IN lt_nums
  NEXT m = COND #( WHEN n > m THEN n ELSE m )
).

" Approach 3: MAX function (for standard tables)
DATA(lv_max3) = 0.
LOOP AT lt_nums INTO DATA(lv_n2).
  lv_max3 = nmax( val1 = lv_max3 val2 = lv_n2 ).
ENDLOOP.
Exercise 3.1 – Table Type Selection

For each scenario, choose the best internal table type and explain why:

  1. You need to store 500,000 customer records and look up customers by their unique ID very frequently.
  2. You need to read a small configuration table (20 rows) sequentially in a loop.
  3. You need to store 100,000 sales orders and frequently search for all orders belonging to a specific customer (customer ID is not unique per order).
Show Solution – Exercise 3.1
Solution

1. Hashed table. Unique key, very large dataset, frequent unique key lookups. Hashed gives O(1) constant-time access.

2. Standard table. Small dataset, sequential access. Index access is efficient and the table is simple to use.

3. Sorted table. Non-unique key (customer ID), large dataset, frequent key-based reads. Sorted tables support binary search (O(log n)) and allow non-unique keys.

Exercise 3.2 – Method to Find the Highest Number

Write a method that takes a STANDARD TABLE OF i and returns the highest number. Use modern syntax. Handle the case where the table is empty.

Show Solution – Exercise 3.2
Solution 
CLASS zcl_step1_utils DEFINITION
  PUBLIC
  FINAL
  CREATE PUBLIC.

  PUBLIC SECTION.
    CLASS-METHODS get_highest
      IMPORTING it_numbers TYPE STANDARD TABLE OF i
      RETURNING VALUE(rv_max) TYPE i.

ENDCLASS.

CLASS zcl_step1_utils IMPLEMENTATION.
  METHOD get_highest.
    IF it_numbers IS INITIAL.
      rv_max = 0.
      RETURN.
    ENDIF.

    rv_max = REDUCE i(
      INIT m = 0
      FOR n IN it_numbers
      NEXT m = COND #( WHEN n > m THEN n ELSE m )
    ).
  ENDMETHOD.
ENDCLASS.
💡 Note REDUCE handles the empty table gracefully because the INIT value is 0 and no iterations occur, so rv_max stays 0.

4. ABAP SQL

ABAP SQL is the modern way to access data in ABAP Cloud. It uses host variables (prefixed with @), explicit field lists, and inline declarations.

4.1 Basic SELECT

" Old style (avoid in ABAP Cloud)
SELECT * FROM mara INTO TABLE lt_mara.

" Modern style – explicit fields, inline declaration, host variable
SELECT matnr, mtart, matkl
  FROM mara
  WHERE mtart = @lv_mtart
  INTO TABLE @DATA(lt_materials).

4.2 Host Variables and Host Expressions

Host variables are ABAP data objects used in SQL statements. They must be prefixed with @.

DATA(lv_carrid) = 'LH'.

SELECT carrid, carrname
  FROM scarr
  WHERE carrid = @lv_carrid
  INTO TABLE @DATA(lt_carriers).

4.3 Joins

INNER JOIN

Returns only rows where the join condition matches in both tables.

SELECT a.carrid, a.carrname, b.connid, b.cityfrom, b.cityto
  FROM scarr AS a
  INNER JOIN spfli AS b ON a.carrid = b.carrid
  WHERE a.carrid = @lv_carrid
  INTO TABLE @DATA(lt_flights).

LEFT OUTER JOIN

Returns all rows from the left table, plus matching rows from the right table. If no match exists, right-side fields are NULL.

SELECT a.carrid, a.carrname, b.connid, b.cityfrom
  FROM scarr AS a
  LEFT OUTER JOIN spfli AS b ON a.carrid = b.carrid
  INTO TABLE @DATA(lt_all_carriers).
📌 Exam Tip The default join type is INNER JOIN. If you write JOIN without specifying, ABAP treats it as INNER JOIN.

4.4 Aggregation

" Count, sum, average, max, min
SELECT carrid,
       COUNT(*) AS flight_count,
       MAX( distance ) AS max_distance,
       AVG( distance ) AS avg_distance
  FROM spfli
  GROUP BY carrid
  HAVING COUNT(*) > 1
  INTO TABLE @DATA(lt_stats).

4.5 Code Pushdown

Code pushdown means moving data-intensive logic from the ABAP application server to the database (SAP HANA). Instead of reading all data into ABAP and processing it in a loop, you let the database do the heavy lifting.

Without Code Pushdown (Slow) With Code Pushdown (Fast)
Read all rows into an internal table, then loop to filter/sum Use WHERE, GROUP BY, and aggregations in SQL
Multiple SELECT statements for related data Use JOIN to combine tables
Classic Open SQL with SELECT * Modern ABAP SQL with explicit fields and host variables

Exercise 4.2 – Code Pushdown

You have a table sflight with columns carrid, connid, fldate, and seatsmax. Write a query that returns the total maximum seats per carrier, but only for carriers with more than 5 flights. Sort by total seats descending.

5. CDS Views

Core Data Services (CDS) views are the foundation of the RAP data model. In ABAP Cloud, you cannot access database tables directly in many cases — you must use CDS views.

5.1 Interface View vs. Projection View

Aspect Interface View (ZI_) Projection View (ZC_)
Purpose Core data model — defines the business entity Exposes data for a specific use case (Fiori app, API)
Data Source Directly accesses database tables Built on top of interface views
Fields All relevant business fields, associations Only the fields required by the consumer
Annotations Core semantic annotations (e.g., @Semantics) UI annotations (e.g., @UI), search annotations
Reusability Reusable across multiple applications Specific to one application or service
Naming ZI_<EntityName> ZC_<EntityName>
📌 Why Two Layers?
  • Separation of concerns — the interface view defines what the data is; the projection view defines how it looks to a specific consumer.
  • Reusability — multiple projection views can be built on one interface view for different apps.
  • Stability — changes to the UI don't affect the core data model.

5.2 Creating a Simple Interface View

@AccessControl.authorizationCheck: #NOT_REQUIRED
@EndUserText.label: 'Flight Interface View'
define view entity ZI_Flight
  as select from spfli
{
  key carrid,
  key connid,
      cityfrom,
      cityto,
      deptime,
      arrtime,
      distance,
      distanceid
}

5.3 Creating a Projection View

@AccessControl.authorizationCheck: #NOT_REQUIRED
@EndUserText.label: 'Flight Projection View'
@UI.headerInfo: { typeName: 'Flight', typeNamePlural: 'Flights' }
define view entity ZC_Flight
  as select from ZI_Flight
{
  key carrid,
  key connid,
      @UI.lineItem: [{ position: 10 }]
      cityfrom,
      @UI.lineItem: [{ position: 20 }]
      cityto,
      distance
}

5.4 Associations in CDS

define view entity ZI_Carrier
  as select from scarr
  association [0..*] to ZI_Flight as _Flights
    on $projection.carrid = _Flights.carrid
{
  key carrid,
      carrname,
      currcode,
      _Flights
}
Exercise 5.1 – CDS View Layers

Explain in your own words:

  1. Why does SAP use two CDS layers (interface + projection) in RAP?
  2. If you need to add a UI annotation (e.g., a field label), which layer do you modify? Why?
  3. If you need to add a new business field to the data model, which layer do you modify? Why?
Show Solution – Exercise 5.1
Solution

1. Separation of concerns and reusability. The interface view defines the core business entity and can be reused by multiple projection views. The projection view tailors the data for a specific consumer (e.g., a Fiori app) without polluting the core model with UI-specific details.

2. Projection view (ZC_). UI annotations are consumer-specific. They belong in the projection layer, not in the reusable core data model.

3. Interface view (ZI_). Business fields are part of the core data model. Adding them at the interface level makes them available to all projection views built on top.

6. ABAP Cloud & Clean Core

ABAP Cloud is not a separate language — it is a restricted ABAP language version that enforces cloud-ready, upgrade-safe development. It is the foundation of SAP's Clean Core strategy.

6.1 What Is ABAP Cloud?

ABAP Cloud is a development model for SAP BTP ABAP Environment and S/4HANA Cloud that enforces:

  • Only released APIs from SAP may be used.
  • Only ABAP for Cloud Development language version is allowed.
  • No direct database access to non-released tables.
  • No modification of SAP standard code.
  • No obsolete or classic statements (e.g., WRITE, TABLES, EXEC SQL).

6.2 Clean Core Principles

Principle What It Means Example
Released APIs only Use only SAP objects with a release contract (C0 or C1) Use I_Product CDS view instead of MARA table
No direct DB access Do not SELECT from non-released tables Use CDS views or released APIs
No modifications Do not change SAP standard objects Use extension points, BAdIs, or RAP
Upgrade-safe Custom code survives SAP upgrades without fixes Stable interfaces via released APIs

6.3 Common ABAP Cloud Violations

🚫 Forbidden in ABAP Cloud
  • SELECT * FROM mara — direct access to a non-released table
  • WRITE — classic output statement (use RAP or console output instead)
  • TABLES — classic table declaration (use DATA)
  • EXEC SQL — native SQL (use ABAP SQL)
  • Modifying SAP standard code via MODIFY or enhancements

6.4 Finding Released APIs

SAP provides the ABAP Cloud API State in ADT. To check if an object is released:

  1. Open the object in ADT (e.g., a CDS view or class).
  2. Check the Properties or API State view.
  3. Look for the release contract: C0 (released for cloud) or C1 (restricted).

6.5 ATC Checks for ABAP Cloud

Always run ATC with the ABAP Cloud check variant before considering your code done. This catches:

  • Use of non-released APIs
  • Forbidden language constructs
  • Direct database access violations
  • Syntax not allowed in the cloud language version

7. Object-Oriented Design

ABAP Cloud is object-oriented at its core. You must understand the difference between static and instance methods, and when to use each.

7.1 Static vs. Instance Methods

Aspect Static Method Instance Method
Declaration CLASS-METHODS METHODS
Call Syntax zcl_class=>method( ) lo_obj->method( )
Access to Attributes Static attributes only All attributes (static + instance)
Object State No object state — shared by all instances Can use and modify instance state
Unit Testing Harder to mock Easier to mock and inject dependencies
When to Use Utility functions with no state (e.g., string helpers, math helpers) Business logic that depends on object state
📌 Clean ABAP Guidance SAP's Clean ABAP style guide recommends preferring instance methods over static methods, because instance methods:
  • Better reflect object-oriented design
  • Can be overridden in subclasses
  • Can be mocked in unit tests
Use static methods only for utility functions or factory methods.

7.2 Class Definition Example

CLASS zcl_step1_math DEFINITION
  PUBLIC
  FINAL
  CREATE PUBLIC.

  PUBLIC SECTION.
    " Static method – utility, no state
    CLASS-METHODS add
      IMPORTING iv_a TYPE i
                iv_b TYPE i
      RETURNING VALUE(rv_sum) TYPE i.

    " Instance method – uses object state
    METHODS constructor
      IMPORTING iv_base TYPE i.

    METHODS multiply_by_base
      IMPORTING iv_factor TYPE i
      RETURNING VALUE(rv_result) TYPE i.

  PRIVATE SECTION.
    DATA mv_base TYPE i.
ENDCLASS.

CLASS zcl_step1_math IMPLEMENTATION.
  METHOD add.
    rv_sum = iv_a + iv_b.
  ENDMETHOD.

  METHOD constructor.
    mv_base = iv_base.
  ENDMETHOD.

  METHOD multiply_by_base.
    rv_result = mv_base * iv_factor.
  ENDMETHOD.
ENDCLASS.

7.3 Calling the Methods

" Static method – called via class name
DATA(lv_sum) = zcl_step1_math=>add( iv_a = 10 iv_b = 20 ).
" Result: 30

" Instance method – called via object reference
DATA(lo_math) = NEW zcl_step1_math( iv_base = 5 ).
DATA(lv_product) = lo_math->multiply_by_base( iv_factor = 4 ).
" Result: 20

  DURATION SHORT
  RISK LEVEL HARMLESS.

    METHODS test_negative FOR TESTING.
    METHODS test_zero FOR TESTING.

Question 1 – Modern Syntax

What is the output of this code?

DATA(nums) = VALUE i_table( ( 3 ) ( 7 ) ( 2 ) ( 9 ) ( 5 ) ).
DATA(result) = REDUCE i(
  INIT x = 0
  FOR n IN nums
  WHERE ( n > 4 )
  NEXT x = x + n
).
WRITE / result.
Show Answer – Q1
Answer

Output: 21

The WHERE condition filters to numbers greater than 4: 7, 9, 5. The REDUCE sums them: 7 + 9 + 5 = 21.

You have a hashed internal table lt_data with a unique key on id. Which of these statements is invalid?

  2. READ TABLE lt_data INTO DATA(ls) INDEX 1.

Question 3 – ABAP SQL

Write an ABAP SQL statement that joins scarr and spfli on carrid and returns carrid, carrname, and connid for a given carrid.

Show Answer – Q3
Answer 
SELECT a.carrid, a.carrname, b.connid
  FROM scarr AS a
  INNER JOIN spfli AS b ON a.carrid = b.carrid
  WHERE a.carrid = @lv_carrid
  INTO TABLE @DATA(lt_result).
Question 4 – CDS Views

What is the difference between an interface view (ZI_) and a projection view (ZC_)? Why does SAP use two layers?

Show Answer – Q4
Answer

Interface view (ZI_) defines the core business data model. It directly accesses database tables, contains all relevant business fields and associations, and is reusable.

Projection view (ZC_) is built on top of the interface view. It exposes only the fields needed for a specific consumer (e.g., a Fiori app), adds UI annotations, and is not reusable across different apps.

Two layers provide separation of concerns: the core data model stays stable and reusable, while UI-specific details are isolated in the projection layer.

Question 5 – ABAP Cloud

Why is SELECT * FROM mara not allowed in ABAP Cloud? How would you fix it?

Show Answer – Q5
Answer

MARA is a non-released database table. ABAP Cloud only allows access to released APIs (e.g., released CDS views) to ensure upgrade stability and Clean Core compliance.

Fix: Use a released CDS view such as I_Product instead of the MARA table. For example:

SELECT Product, ProductType
  FROM I_Product
  WHERE Product = @lv_matnr
  INTO TABLE @DATA(lt_products).
Question 6 – OO Design

What is the difference between a static method and an instance method? When would you use each?

Show Answer – Q6
Answer

Static method: Called via class name (zcl_class=>method). Can only access static attributes. Used for utility functions with no object state.

Instance method: Called via object reference (lo_obj->method). Can access all attributes (static and instance). Used for business logic that depends on object state.

Guidance: Prefer instance methods for business logic (easier to test and mock). Use static methods only for pure utility functions or factory methods.
